# Commands page as documentation (CLI and Desktop)

Rewrite `/commands` in the documentation style of [opencode.ai/v2/docs](https://opencode.ai/v2/docs): a left sidebar with a CLI group and a Desktop group, and one section per topic with a short explanation, copyable code blocks, and its options as a short list.

Design approved by the user in chat on 2026-10-28. Execution mode: all stories (approved 2026-10-28).

## Constraints

- Every user-facing string in English and Spanish; flags, commands, and identifiers stay in English.
- Existing design tokens (`--color-*`, `--font-*`), Line Awesome icons, no new libraries.
- Components re-render on the language toggle (`OnLanguageChanged` pattern from `CLAUDE.md`).
- Source code is generated by the local model first (`AGENTS.md`); the agent reviews, applies, and verifies.
- Desktop facts are taken from `../../Desktop/llmtuner/src/web/public/index.html`, `app.js`, and `src/i18n/*.js`, not invented.

## US-01 — Section data and CLI content

As a reader, I want each CLI command explained in its own section, so that I understand what it does before reading flags.

**Acceptance criteria**

1. `Models/SiteModels.cs` gains a section model: id (anchor), group (`cli` / `desktop`), title, short body paragraphs, code examples, and an option list (flag, description, default).
2. `DocumentationDataService` exposes the sections, localized like the existing getters (`isEs`).
3. CLI sections, in this order: Intro (interactive menu), `/load`, `/mcp`, `/presets`, `/serve`, `/settings`, `/help` and `/exit`, Automation (`--yes`, `--json`, `--dry-run`, `--server`), Options reference.
4. Options reference reuses `GetCommands()` data, grouped by topic.
5. Every flag listed today on `/commands` still appears somewhere in the CLI group.

**Dependencies**: none.

**Verification**: `dotnet build`; compare the flag list on the new page with `GetCommands()`.

**Status**: complete

## US-02 — Documentation layout on `/commands`

As a reader, I want a sidebar and readable sections instead of a filtered table, so that I can find and follow a command quickly.

**Acceptance criteria**

1. `/commands` shows a left sidebar with the "CLI" and "Desktop" groups; each item links to its section anchor and the sidebar stays visible while scrolling on desktop widths.
2. At 375 px width the sidebar becomes a compact menu above the content, with no horizontal page scroll.
3. Each section renders its heading, body, code blocks with the existing `CopyButton`, and options as a list.
4. The category-filter table is removed.
5. The interactive command builder remains, as the last section of the CLI group.
6. The page and its components switch language immediately with the EN/ES toggle.

**Dependencies**: US-01.

**Verification**: preview `/commands` in English and Spanish; click every sidebar link; check 375 px and desktop widths; console free of errors.

**Status**: complete
