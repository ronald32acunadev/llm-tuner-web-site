# Components follow the language toggle

Execution mode: all stories (approved by the user in chat: "Yes, fix it").

## US-01 — Embedded components switch language immediately

As a visitor, I want every part of a page to switch language when I use the EN/ES toggle, so that I don't see a page mixing English and Spanish.

**Acceptance criteria**

1. `CommandBuilder`, `TerminalMockup`, `DesktopAppMockup`, and `ProfileComparator` re-render when `DocumentationDataService.OnLanguageChanged` fires, without reloading or changing page.
2. Each one follows the existing page pattern: `@implements IDisposable`, subscribe in `OnInitialized`, `InvokeAsync(StateHasChanged)` in the handler, unsubscribe in `Dispose`.
3. Component state (selected tab, builder inputs) is kept when the language changes.

**Dependencies**: none.

**Verification**: reproduce the bug first (toggle ES on `/commands`, `/profiles`, `/showcase` and see English remain), then after the fix the same steps show Spanish; `dotnet build` passes.

**Status**: complete

**Implementation**: the lifecycle members were generated by the local model (LM Studio, `google/gemma-4-31b-qat`) and match the existing page pattern; they were inserted into the four components unchanged (`ProfileComparator` gets a new `@code` block).

**Observed after the fix (2026-10-28)**: `dotnet build` passes with 0 errors. Toggling ES without changing page switched `CommandBuilder` (and kept `--server gpu-rig` in the preview), `ProfileComparator`, `TerminalMockup` ("Copiar Comando"), and `DesktopAppMockup` (step titles); toggling back to EN restored English.

**Observed before the fix (2026-10-28)**: toggling ES left `CommandBuilder`, `ProfileComparator`, and `TerminalMockup` in English.
