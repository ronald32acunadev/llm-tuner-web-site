# Command builder: `--server` option

Execution mode: all stories (approved by the user in chat: "Yes, add it").

## US-01 — Target a remote server from the command builder

As a visitor building an `llm-tuner` command, I want to enter a saved remote server, so that the generated command targets that server with `--server`.

**Acceptance criteria**

1. `Components/CommandBuilder.razor` shows a "Server (--server)" text field, labelled in English and Spanish, with a hint that empty means the local machine.
2. When the field is empty or whitespace, the generated command is unchanged (no `--server`).
3. When it has a value, the command includes `--server <value>` right after `llm-tuner`, with surrounding whitespace trimmed.
4. A value that contains whitespace is wrapped in double quotes.
5. The copy button copies the same command as the preview.

**Dependencies**: none.

**Verification**: `dotnet build`, then on `/commands` in the preview: empty field, `gpu-rig`, and `my rig` produce the expected commands, in English and Spanish.

**Status**: complete

**Implementation**: generated by the local model (LM Studio, `google/gemma-4-31b-qat`), reviewed and applied without corrections.

**Observed verification (2026-10-28)**

- `dotnet build`: 0 warnings, 0 errors.
- Empty and whitespace-only field: `llm-tuner --engine lmstudio --model qwen/qwen2.5-coder-32b --ctx 16k --profile balanced --yes` (unchanged).
- `  gpu-rig `: `llm-tuner --server gpu-rig --engine lmstudio ...`.
- `my rig`: `llm-tuner --server "my rig" --engine lmstudio ...`.
- Spanish label "Servidor (--server):" and hint "Vacío = esta máquina" render after the page re-renders.

**Known issue (pre-existing, not part of this story)**: `CommandBuilder` does not subscribe to `OnLanguageChanged`, so toggling the language on `/commands` leaves the whole builder in the previous language until the page is reloaded or revisited.
